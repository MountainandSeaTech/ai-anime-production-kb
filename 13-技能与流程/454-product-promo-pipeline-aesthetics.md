# 产品宣传片制作流水线与判例式审美准则

## 一、八阶段制作流水线

> 核心原则：**方向性问题不进昂贵的逐镜头阶段**。验收贯穿全程，不是最后一个阶段。

| 阶段 | 目标 | 关键产出 | 铁律 |
|---|---|---|---|
| 0 产品理解 | 只读检查定位/功能/视觉/数据风险 | 产品简报 + 需求决策表 | 敏感数据先虚构/脱敏/冻结 |
| 1 视觉方向 | 最便宜产物锁定色板/字体/光感/运镜气质 | styleframe + 动效参数 tokens | **不渲染视频**，用 HTML/CSS 静态帧定调 |
| 2 功能到镜头映射 | 为每个功能选运动语法 | 功能→镜头映射表 | 一种手法全片只当一次主角 |
| 3 分镜与制作放行 | 排成有能量曲线的完整序列 | 设计 spec + 帧级时间轴 | 预留 hold/rest 帧预算 |
| 4 最终素材采集 | 按分镜拿真实页面素材 | 全页图 + 元素切片 + layout.json | 分镜放行前不做全量采集 |
| 5 逐镜头实现 | 按帧级时间轴逐镜落地 | 逐镜头 commit + 静帧档案 | 每镜先解析 demo 源码再实现 |
| 6 声音设计 | BGM 定骨架 + SFX 逐拍钉帧 | 带声整片 + SFX 钉帧表 | **画面锁定后才做声音** |
| 7 独立终检 | 对照审美准则正式自检 | 自检报告 + 成片 | 派干净 subagent 独立审查 |

### 流水线两大执行原则

1. **最终设计 spec 与分镜共同构成制作放行**：分镜表长在设计 spec 里（`| # | 时间 | 镜头 | 关键动效 |` 四列）；确认放行不重新打开已确认的业务或创意问题。
2. **验收贯穿全程**：每个镜头用静帧肉眼验收收尾，每轮修改后整片重渲；阶段 7 只是把这套动作升级为对照审美准则的正式自检。

### 常见坑（跨阶段）

- **用渲染视频做风格提案**：太贵，改方向的心理成本也高——静态帧足够定调
- **素材方向错误拖到逐镜头阶段**：整套场景报废——分镜放行前不做全量采集
- **首检交给用户**："镜头视角很差，而且有小抖动"这种问题不该由用户发现
- **画面没锁就铺音效**：全表重钉的连带成本

### C 文案 / P 流程

- **C 类**（文案）：字卡只写一句话、数据用整数、行动号召放最后一镜——产品宣传片专属文案纪律
- **P 类**（流程）：验收贯穿全程、独立终检、确定性渲染（禁 Date.now/Math.random，固定种子）

## 三、产品宣传片专属准则（主线无对应）

以下准则是产品宣传片领域特有，动漫短剧主线不适用但留此存档：

**Q1 真实截图优先**：表现产品既有页面必须用无头浏览器截真实页面（全页纹理+元素级抠图+坐标 json），不手搓仿真贴图。非复刻场景允许手搓 UI 但质量/表达是硬门槛。

**Q8 发布会合影收尾**：多功能产品收尾用"全家福"结构——每个已展示功能抽一个代表元素多方向飞入定格；规格匹配全片能量峰值（crane 运镜+舞台光+粒子），初版收尾几乎总是偏保守，默认加码一档。

**Q9 飞入终点落地**：元素飞入后要"嵌入"页面（归位到真实格位、扩展滚动流），不落地悬浮其上会显得假。

**Q10 文档 mock 出版级**：观众会读清屏幕上每个字——文档/报告类镜头必须用产品原生排版灌满真实密度的假内容，侧栏/评论栏等版式元素完整入镜。

**P 确定性渲染**：禁 Date.now()/Math.random()，一切伪随机固定种子（mulberry32/哈希，seed 从 index 派生），逐帧可复现。
