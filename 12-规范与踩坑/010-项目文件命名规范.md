# AI 视频项目文件命名与目录规范

## 核心要点
- 命名规范从项目第一天就要定，后期补成本极高
- 镜号是主键，所有资产（视频/音频/分镜/参考图）按镜号关联
- 版本号用后缀 `_v01 _v02`，不用「最终版」「真的最终版」这种命名

## 项目根目录结构
```
项目名/
├── 01_剧本/            # 故事大纲、分集剧本
├── 02_角色卡/          # 角色设定图、参考切片
│   └── 角色名/
│       ├── 母卡_v01.png
│       ├── 切片/
│       └── 提示词.txt
├── 03_场景卡/          # 场景设定图
├── 04_分镜/            # 分镜表、分镜示意图
│   └── S01_分镜表.md
├── 05_生成/            # AI 视频生成产物
│   └── S01/
│       ├── S01-001_v01.mp4
│       ├── S01-001_v02.mp4
│       └── S01-002_v01.mp4
├── 06_配音/            # TTS 配音
│   ├── 台词.md
│   └── S01-001.wav
├── 07_音效/            # SFX、BGM
│   ├── SFX/
│   └── BGM/
├── 08_合成/            # 口型同步、剪辑产物
│   ├── 口型同步/
│   └── 剪辑工程/
├── 09_成品/            # 最终输出
│   └── S01_最终版.mp4
└── 99_失败样本/        # 失败案例积累
```

## 镜号命名规范
- 格式：`S{集号}-{镜号3位}`
- 示例：`S01-001`、`S02-015`、`S03-127`
- 镜号在分镜表确定后冻结，不重排

## 文件命名规范

### 视频生成产物
`{镜号}_v{版本号}.mp4`，例：`S01-001_v01.mp4`
- 每次重新生成版本号 +1，旧版保留
- 选定版本复制一份去掉版本号作为「正式版」：`S01-001.mp4`

### 角色卡
`{角色名}_母卡_v{版本号}.png`，例：`雪菜_母卡_v01.png`
- 切片命名：`{角色名}_{视角}.png`，例：`雪菜_正面.png`、`雪菜_侧面.png`

### 配音
`{镜号}.wav`，例：`S01-001.wav`，与分镜镜号一一对应

### 分镜表
`S{集号}_分镜表.md`，例：`S01_分镜表.md`

## 版本号规则
- 新生成/迭代：`_v01 → _v02 → _v03`
- 选定版：去掉版本号作为正式版
- 重大修改回到 `_v01` 重排，不要在 v05 上继续改到 v20
- 旧版本不删，移到 `99_失败样本/` 或 `归档/`

## 关联键
- 镜号 `S01-001` 是主键：分镜表、生成产物、配音、合成全部用此关联
- 角色名是次级键：角色卡、参考图、配音模型按角色名关联
- 检索时按镜号一查，所有资产都串起来

## 备注
- 命名规范定下后，写一个 `命名检查.ps1` 脚本定期扫描违规命名
- 「最终版」「真·最终版」「真的最终版」是版本管理崩塌的信号，坚决禁止
- 云盘备份：项目整目录每周打包一次，版本号 `项目名_YYYYMMDD.zip`
- 团队协作时，命名规范文档放项目根目录 `README.md`

## WAN3.0 校准（2026-10-20）

WAN3 本地编辑产物命名规则，补齐原规范：
- 局部编辑版本号：`{镜号}_v{版本号}_edit_v{编辑序号}.mp4`，例：`S01-001_v02_edit_v01.mp4`，同一镜头经 WAN3 本地编辑的版本单独递增 edit 序号。
- 编辑区域时间码：对应提示词文件命名 `{镜号}_v{版本号}_edit_v{编辑序号}_range_{起始秒}-{结束秒}.md`，例：`S01-001_v02_edit_v01_range_12-18.md`，记录本次编辑覆盖的时间范围（秒），便于后续追溯。
- 提示词补丁文件：每个本地编辑版本留一份独立 patch 文件，命名 `{镜号}_v{版本号}_edit_v{编辑序号}_patch.md`，内容为本次编辑的新增/修改 prompt 片段，便于审计与跨镜复用。
- WAN3 30s 原生整段产物可按 `{镜号}_v{版本号}_wan3_native.mp4` 归档，标注模型来源，与旧模型产物分开管理。
