# H3 vs Wan选型指南

## 核心要点
- 没有最强模型，只有**最合适的模型×场景组合**
- H3（MiniMax海螺）：指令运镜精确/中文友好/人物表演强
- Wan（阿里万相）：分镜式写法/首尾帧成熟/物理质感强
- 实战策略：**同一份提示词两模型同跑，对比选片**（Morphic等平台原生支持）
- 关联 141 H3指令、143 Wan公式

## 对比详解

### 提示词语法差异
```
H3：自然语言 + [指令]方括号运镜
Wan：纯自然语言（含运镜描述）+ Shot分镜格式
```
- **迁移成本**：一套提示词不能直接用，运镜部分要改写
- 迁移对照表见143条目

### 核心长项对比（Wan3.0 为当前默认基准模型）

| 维度 | H3 | Wan 3.0 |
|---|---|---|
| 单段时长 | 15s（节拍式切分） | **30s 原生**（上限非建议值） |
| 帧率 | 24fps | **30fps**（顺滑运动/慢动作够用） |
| 分辨率 | 720P | **480P/720P/1080P** 三档可选，1080P 基准 |
| 运镜控制 | [指令]精确制导 | 自然语言描述（更贴近影视脚本） |
| 中文理解 | 原生强项（国产） | 良好（通义系） |
| 人物表演/微表情 | 强项 | 中等 |
| 物理规律/材质 | 良好 | 强项 |
| 多镜头分镜 | 单镜为主 | Shot 格式原生 |
| 首尾帧 | 支持 | 支持且文档成熟 |
| 音频 | 需后配或手动写描述 | **原生音画**（BGM+音效随画面同步生成） |
| 多模态参考 | 有限 | **10图+5视频+5音频** 上限（角色脸/动作锁/BGM引导） |
| 本地编辑 | 不支持 | **选段改提示词局部替换**（漂移≤3s时优先） |
| 风格化/动漫 | 良好 | 强项（2.2 MoC 风格继承） |
| 限流/价格 | 平台差异大 | **300 RPM** ｜ ¥0.3/0.6/1.2 每秒（480/720/1080P） |

### 选型结论（2026-10-20 校准）

> **Wan 3.0 作为默认生成模型，H3 保留用于精确运镜指令的分镜预览阶段**

| 场景 | 选型 | 理由 |
|---|---|---|
| 常规生成（角色+动作+场景+音画一体） | **Wan 3.0** | 30s 原生/30fps/原生音画/多模态参考上限全覆盖 |
| 角色脸崩/微表情失控 | 先 Wan 3.0，不行补 H3 预览 | Wan3 多模态正典脸参考（10图内 4 张正典脸）已能锁脸；极端情况才用 H3 做单镜预览 |
| 精确运镜指令（如[Orbit left, Push in]并发） | **H3（仅分镜预览）** | H3 [指令]语法在复杂运镜并发上仍有优势——先用 H3 跑 15s 预览确认运镜轨迹，再转 Wan 3.0 生成完整 30s 段 |
| 本地编辑（段内漂移≤3s） | **Wan 3.0** | H3 不支持，Wan3 选段改提示词局部替换即可修复 |
| 批量生成/成本敏感 | **Wan 3.0 480P** | ¥0.3/s 最低档，300 RPM 限流够日常跑 |

**实战策略**：Wan3.0 主生成 + H3 精确运镜预览辅助——不搞"全 H3 全 Wan"二选一，而是 H3 把复杂运镜路线先跑通预览，Wan 3.0 按预览轨迹展开完整 30s 段。

### 按镜头类型选型

#### 情绪特写/微表情戏 → H3
```
理由：人物面部表演细节强，[Push in]指令精确控制逼近节奏
关联 161-170 微表情专题
```

#### 大场面/物理特效 → Wan
```
理由：爆炸/水流/布料/烟尘的物理真实感强
例：战斗烟尘、雨、火焰
```

#### 精确运镜设计 → H3
```
理由：[Orbit left, Push in]并发指令=环绕推近的精确高光镜头
```

#### 多镜头一次成型 → Wan 3.0
```
理由：Shot 1 [0-2s]格式=单提示词生成完整场景
适用：快速原型/分镜验证
```

#### 首尾帧精密控制 → Wan
```
理由：首尾帧API/文档成熟，过渡描述规范清晰
```

#### 中文意境/武侠风 → H3略优
```
理由：国产模型对"剑气/侠客/水墨"等词理解更深
```

## 双跑工作流（推荐）

### 流程
```
1. 写中性提示词（不含模型专属语法）
2. 分别加模型语法：
   H3版：运镜改[指令]
   Wan版：运镜自然语言化
3. 两模型同跑
4. 对比选片，记录"谁擅长什么"到个人经验库
```

### 中性提示词层（双模型兼容的核心）
```
中性层 = 主体锚点 + 动作 + 场景 + 光线 + 氛围
（运镜不写=留给语法适配层）
```
- 中性层可直接复用，语法层分别适配=一稿两投

### 选片标准（按优先级）
```
1. 主体不崩（脸/手/武器不变形）
2. 运动符合提示词（方向/幅度对）
3. 构图可用（兴趣点位置对）
4. 质感加分（光/材质/粒子）
```

## 模板示例（同一镜头双语法）

 雨夜神社，冷蓝月光。孤独氛围。"
```

 雨夜神社，冷蓝月光逆光，雨声渐弱"
```

```
"Medium shot of a silver-haired swordsman sheathing his katana

```

## 常见坑
- **语法混写**：Wan提示词里塞[Push in]=指令失效
- **一次定终身**：某模型一次翻车就拉黑=样本不足，同提示词至少抽3次
- **忽略模型更新**：模型版本迭代快，上月短板这月可能补上=定期重测
- **成本错位**：简单镜头用贵模型=浪费；按镜头难度分配模型预算
- **平台差异**：同一模型在不同平台（官网/聚合平台）可能有参数差异=固定平台测试

## 进阶
- **分工流水线**：H3出人物戏+Wan出大场面+剪辑缝合=各取所长
- **建立个人模型卡**：每个模型记录"长项/短板/翻车场景/最佳参数"=越用越准
- **种子/参数档案**：好结果的种子+参数存档=可复现资产（关联115）
- **关注社区实测**：RunningHub/官方文档的提示词库=站在别人的抽卡次数上
