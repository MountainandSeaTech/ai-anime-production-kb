# H3运镜指令语法

## 核心要点
- H3（MiniMax Hailuo-02/Director系）支持 **[指令] 语法**做运镜控制
- 指令写进 prompt 的方括号里=精确运镜，不写=AI自由发挥
- **同一括号内指令同时执行（最多3个）；分开的括号按顺序执行**
- 括号落在哪个节拍末尾，运镜就在那一拍发生
- 关联 111 提示词公式、129 运镜手法

## 指令系统详解

### 基本语法
```
普通写法（听天由命）：
  "镜头慢慢推近，然后摇向天空"

指令写法（精确制导）：
  "角色站在废墟中 [Push in]，风吹起衣角 [Pan up]"
  = 先推近，推完后上摇
```

### 执行规则
```
[Push in] 单独括号 = 按顺序执行
[Push in, Tilt up] 同括号 = 推近+上摇同时发生
[Push in, Tilt up, Orbit left] = 3个并发的上限
[A][B][C] 连续括号 = A做完做B再做C
```
- 同括号>3个=指令衰减，动作互相打架
- 空节拍（没有文字只放括号）会被跳过

### 15种运镜指令（按功能分组）
```
位移类：
  [Push in] 推近——接近主体，情绪收紧
  [Pull out] 拉远——揭示环境，收束/孤独
  [Truck left/right] 平移——展示横向空间
  [Pedestal up/down] 升降机位——垂直空间
转向类：
  [Pan left/right] 水平摇——巡视/跟随
  [Tilt up/down] 垂直摇——揭示高度/坠落
复合类：
  [Zoom in/out] 变焦（无机位移，画面压缩感）
  [Orbit left/right] 环绕——展示主体全貌=高光时刻
  [Crane up/down] 大升降——史诗感开场/收尾
  [Tracking shot] 跟拍——跟随运动主体
特殊：
  [Shake] 手持晃动——临场/混乱
  [Static] 固定镜头——锁定画面防AI乱动
```

## 节拍写法（Beat式提示词）

### 结构
```
[节拍1画面描述][运镜指令]，[节拍2画面描述][运镜指令]，…
```

### 示例
```
"雨夜天台，少女独自站立 [Static]，
 她缓缓抬头 [Tilt up]，
 泪与雨混在一起 [Push in]，
 远处城市灯火闪烁 [Pull out, Crane up]"
```
- 4拍4指令，节奏=镜头语言节奏
- 每个指令前的文字描述该拍的画面状态

## Push in vs Zoom in（易混点）
```
[Push in] 推近：机身真的前移
  → 前景背景相对移动，空间压缩，"我在接近"
[Zoom in] 变焦：机位不动画面放大
  → 无透视变化，画面扁平，"注意力聚焦"
```
- 情绪逼近用Push；信息聚焦用Zoom
- 关联 020 推拉升降

## 模板示例

### 情绪特写（单指令）
```
"烛光中老人的脸，皱纹里藏着故事 [Push in]"
```

### 揭示场景（双指令顺序）
```
"浓雾中的森林 [Push in]，迷雾散开露出废弃神社 [Tilt up]"
```

### 高光环绕（并发）
```
"觉醒的主角悬浮半空，气场爆发 [Orbit left, Push in]"
```

### 史诗收尾（三连节拍）
```
"战场尘埃落定 [Static]，
 幸存者站起 [Crane up]，
 镜头越过他望向地平线 [Pull out]"
```

## 常见坑
- **指令堆砌**：一句话塞5个指令=AI抽风，单括号最多3个
- **指令与描述矛盾**：文字写"静止站立"却给[Tracking shot]=混乱
- **空括号**：[ ]里没指令=可能被当噪声
- **忽略[Static]**：不要运镜的镜头不写[Static]=AI默认加运动
- **指令+自然语言混写**："[Push in]然后镜头再摇一下"=自然语言部分响应差，统一用指令

## 进阶
- **指令+速度词**：部分版本支持"slowly [Push in]"=速度控制
- **指令锚定情绪**：推近=紧张，拉远=释然，环绕=高光，固定=压抑——指令即情绪（关联020/021）
- **首尾帧+指令**：首帧图锁定构图+指令控制运动=最高控制度（关联144）
- **失败重抽策略**：同一指令重抽3次仍不对=换等价指令（[Push in]→[Zoom in]）或简化节拍
