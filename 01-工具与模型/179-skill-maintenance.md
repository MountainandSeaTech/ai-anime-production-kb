# Skill迭代与维护

## 核心要点
- skill是**活的**，不是写完就死的交付物——模型在迭代，用户在进化，需求在变化
- 维护成本占skill全生命周期的70%——不写维护计划=计划着废弃
- 每次翻车都是skill的进化机会，关键是你记不记、改不改

## 维护的四个触发时机

### 时机1：实战翻车（最常见）
```
场景：skill被调用了，输出错了/没触发/漏步骤
动作：
1. 记录翻车现场：用户输入/期望输出/实际输出/错误原因
2. 定位根因：是description没覆盖？正文没写？还是反模式？
3. 修复：改description/补正文/加边界/加示例
4. 回归测试：178全量跑一遍
5. 更新frontmatter的updated日期
```
- 翻车记录是skill最宝贵的资产——比设计文档值钱

### 时机2：能力扩展
```
场景：skill原来只做A，现在想让它也做B
检查清单：
□ description是否同步更新？（172：能力变了触发条件必须变）
□ 边界是否重新划定？（新能力会不会误触发相邻skill）
□ 正文是否新增了B的独立段落，还是和A混在一起？
□ 测试用例是否覆盖B的输入/输出/异常？
□ 如果B和A差异太大→是不是该拆成两个skill？（180）
```
- 能力扩展不更新description=新能力永远不触发

### 时机3：模型/环境升级
```
场景：底层模型从v2升级到v3，或运行环境变更
动作：
- 重跑全部测试用例（178）
- 重点验证：输出格式是否漂移？工具行为是否变化？
- 更新条目标记：如"基于v3.5模型验证"→改为v4.0
- 如果有breaking change→在skill正文最前面加兼容性说明
```

### 时机4：定期体检（防僵尸）
```
周期：每3个月/每50次调用，取先到者
检查项：
□ 最近一次被调用是什么时候？（3个月没人用=考虑归档）
□ 调用成功率/返工率趋势？
□ 有没有重复建设？（两个skill干同一件事）
□ 关联条目/引用是否全部有效？
□ 标签是否还准确？（知识库膨胀后标签漂移）
```

## 维护文档规范

### Changelog（版本历史）
```markdown
## Changelog
- 2026-10-15: v1.2 - 扩展H3支持，新增3个测试用例
- 2026-10-10: v1.1 - 修复空输入导致崩溃的问题
- 2026-09-01: v1.0 - 初始版本
```
- 别写"v1.2.1-alpha-rc3"这种过度工程版本号——简单v1.0→v1.1够用

### 翻车记录（Failure Log）
```markdown
## Known Issues / Failure Log
- [2026-10-12] 输入为空文件时直接崩溃 → v1.1已修复
- [2026-10-08] 用户说"打戏"触发，说"对战"不触发 → description已补充
```
- 这是给未来的自己/团队看的——下次同类问题秒定位

### 关联资产（Related Assets）
```markdown
## Related
- 依赖skill: [技能A], [技能B]
- 被依赖skill: [技能C]
- 关联知识库条目: 171, 172, 178
```
- 维护依赖图——改一个skill前先看谁会受影响

## 生命周期管理

| 阶段 | 特征 | 动作 |
|---|---|---|
| 活跃期 | 高频调用，持续优化 | 正常维护，定期体检 |
| 稳定期 | 低频调用，质量稳定 | 降低体检频率，归档测试用例 |
| 衰退期 | 长期无人用/被替代 | 标记deprecated，引导到新skill |
| 归档期 | 确认废弃 | 从触发列表移除，保留文件供参考 |

- 归档不是删除——留着给后人当反面教材或考古素材

## 常见坑
- **只写不修**：skill上线后从不更新=技术债累积到无法维护
- **翻车不记录**：同一个坑踩三次=维护了个寂寞
- **description僵尸**：能力扩展了description没改=新能力永远沉睡（172）
- **过度维护**：一个3个月没人用的skill还在每月优化=资源错配
- **删除冲动**：旧skill直接删文件=考古现场被破坏，后人无法学习

## 进阶
- **使用埋点**：记录调用次数/成功率/返工率→数据驱动维护优先级
- **A/B灰度**：大改不直接全量→先小范围验证，稳定再推全
- **自动巡检**：写脚本定期检查skill的frontmatter完整性/关联有效性/索引同步
- **知识回流**：把维护中发现的通用问题沉淀成新知识条目（176），反哺知识库
- **版本快照**：重大修改前备份当前版本，改崩了可一键回滚
