# Skill示例与反模式

## 核心要点
- 一个**输入→输出对例**胜过三段形容词描述——模型抄示例的能力远强于理解抽象要求
- 反模式的价值大于正确示范：知道死在哪，比知道活的好更重要
- 七大反模式来自网络真实skill尸检，每一条都有对应解药

## 示例设计规范

### 基本单元：输入输出对
```markdown
## 示例

输入：
> 帮我把这场打戏写成H3分镜，两个角色在竹林

输出：
| 镜号 | 景别 | 动作 | 提示词 |
|---|---|---|---|
| 01 | 大远景 | A入画狂奔 | ... |
```
- 给一对，不只给输出——模型需要学会"从什么变成什么"
- 示例里的细节密度=模型模仿的颗粒度，示例糊弄=输出糊弄

### 示例三层配置
```
1. 标准例：最典型的输入→输出（必给）
2. 边界例：空输入/异常输入/最小输入怎么处理（防即兴）
3. 反例：画蛇添足的输出长什么样，标注"不要这样"（可选但强力）
```

## 七大反模式尸检报告

### 反模式1：无规划直接执行
```
症状：Agent接到任务直接开干，做到一半发现方向错了
解药：正文第一步强制规划——"执行前先输出步骤清单，用户确认或默认后继续"
```
### 反模式2：单体巨兽
```
症状：一个skill挂50个工具，模型选工具时精神错乱
解药：拆分；一个skill干一件事；工具超过10个就该警惕（180）
```
### 反模式3：无自我验证
```
症状：跑完就交差，输出是错的也不知道
解药：正文末尾加验证步骤——"输出前对照XX清单自检"（参考140的QA打勾表思路）
```
### 反模式4：硬编码工具序列
```
症状："第一步必须调A工具第二步必须调B工具"——环境稍变就全崩
解药：描述目标让模型选工具；只在顺序真有因果依赖时才固定序列（175）
```
### 反模式5：无护栏
```
症状：skill能删文件能发消息，一次幻觉=一场事故
解药：最小权限原则——只读skill别声明写权限；破坏性操作强制确认（175）
```
### 反模式6：无状态管理
```
症状：多步任务中间状态丢在对话里，上下文一长就失忆
解药：中间产物落盘——"每步结果写入 work/ 目录，后续步骤从文件读"（177）
```
### 反模式7：只测happy path
```
症状：正常输入完美，用户给个空文件/错格式直接幻觉编造
解药：边界例进正文+异常测试进验收（178）
```

## 附加死法：解析脆弱
```
症状：skill要求模型输出特定格式再用脚本解析，
     模型输出轻微变体 → 解析器崩 → 整个流程崩
解药：
- 能结构化就结构化（JSON mode/function calling）
- 解析脚本写宽容：提取失败时返回错误让模型重试，别直接crash
- 正则解析LLM输出=在流沙上盖楼，能免则免
```

## 反模式自查表（写完skill逐项打勾）
```
□ 正文第一步是不是规划/检查，而非直接执行？
□ 工具数量是否<10？权限是否最小化？
□ 有没有自检/验证步骤？
□ 工具调用是目标导向还是硬编码顺序？
□ 破坏性操作有没有确认门槛？
□ 中间状态是否落盘？
□ 边界例（空/异常输入）有没有覆盖？
□ 解析模型输出的代码是否宽容？
```

## 常见坑
- **示例与正文矛盾**：正文说"简洁输出"，示例给了800字——模型信示例不信正文
- **反例不标注**：贴了错误示例没写"这是错的"——模型当成第二个正确示例学了
- **示例太完美**：示例里的输入都是标准格式=模型遇到脏输入直接傻眼
- **自查表写完不看**： checklist是给自己用的，不是行为艺术

## 进阶
- **反模式库私有化**：把自己skill的翻车案例积累成个人反模式库，新skill写完先过一遍（179）
- **示例差分测试**：改一个词看输出变化——示例里每个词都该有影响，没影响的词是噪声
- **从生产事故反向提取**：每次skill翻车，问"这对应哪个反模式"，没有就新增一条
- **示例即文档**：好的示例集可以替代一半正文——观众（模型）是视觉动物

## 备注
- 输入输出对是示例的基本单元，示例>形容词
- 七大反模式：无规划/巨兽/无验证/硬编码/无护栏/无状态/只测顺境
- 解析LLM输出要宽容，结构化优先
