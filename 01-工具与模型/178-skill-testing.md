# Skill测试与验证

## 核心要点
- "能跑通"不等于"能用"——测试验证的是**触发对不对、输出对不对、边界扛不扛、改完破没破**
- 不写测试的skill=定时炸弹，你根本不知道它什么时候炸
- 测试用例从**真实用户的真实问法**中来，不是开发者臆想的理想输入

## 五层测试体系

### 第一层：触发测试（171/172的实战检验）
```
测试矩阵：
- 同义词：用户说"分镜"/"打戏"/"对战编排"/"分镜头"→都能触发？
- 误触发：用户说"帮我写个剧本"→不该触发的skill不触发？
- 边界触发：用户只说了一半需求→skill反问还是瞎猜？
```
- 通过标准：目标触发率>90%，误触发率<5%

### 第二层：输入测试（174反模式7）
```
必测输入：
- 标准输入（ happy path ）
- 最小输入（只给必需字段）
- 空输入/null
- 格式错误输入（json传成字符串/路径不存在）
- 超边界输入（100MB文件/1000行文本）
- 注入攻击输入（提示词注入/路径穿越）
```
- 每个非标准输入都要有明确的行为定义（报错/反问/降级）

### 第三层：输出验证（不是看一眼就行）
```
验证项：
- 格式合规：Markdown/HTML/JSON是否符合模板
- 内容完整：模板字段是否全部填充
- 内容准确：抽样核对事实/参数/引用
- 文件产出：产物是否真的写入指定路径
- 大小限制：输出是否超限/截断
```
- 写自动化检查脚本，别全靠人眼——人眼会瞎，脚本不会

### 第四层：异常注入（主动搞破坏）
```
注入点：
- 工具失败：模拟API超时/返回错误
- 文件损坏：模拟产物文件写入一半中断
- 权限不足：模拟目标目录只读
- 并发冲突：模拟两个Agent同时写同一文件
```
- 通过标准：skill有定义明确的失败行为（重试/回滚/报错），不是直接崩溃

### 第五层：回归测试（改一次全绿才算完）
```
改动后必跑：
- 全部触发测试用例
- 全部输入测试用例
- 关键输出验证用例
- 受影响步骤的异常注入
```
- 改description→重跑触发测试；改正文→重跑输出验证；改工具链→重跑全流程

## 测试用例怎么写
```markdown
## 测试用例模板
用例ID: T001
类型: 触发测试
用户输入: "帮我把这段打戏写成H3分镜"
预期: 触发skill，生成故事板包
通过条件: skill被调用，输出文件存在于output/
关联需求: 分镜生成流程

用例ID: T007
类型: 输入测试-异常
用户输入: "生成视频"（无文件无参数）
预期: skill反问必需参数，不瞎猜
通过条件: 输出包含"请提供XX文件/参数"
```
- 用例存档，不是跑完就扔——改代码时它们是你的回归资产

## 常见坑
- **只测happy path**：正常输入全绿，真实用户给个脏数据直接炸（174反模式7）
- **测试数据太干净**：用完美格式的测试数据=测试通过线上崩，测试数据必须带脏样本
- **不测触发只测执行**：skill根本不触发=正文写得再好也是废铁
- **不测误触发**：一个skill什么都触发=所有相邻skill都被污染
- **回归测试偷懒**：改了一个字段跑了一个用例就交差=破窗效应的开端
- **测试环境≠生产环境**：本地全绿线上全红，环境差异（路径/权限/网络）必须在测试覆盖内

## 进阶
- **测试覆盖率**：不是代码覆盖率，是用例覆盖率——关键路径/关键分支/关键边界必须有用例
- **快照对比**：输出产物和上次基线对比，diff超阈值自动报警
- **模糊测试**：随机生成100个畸形输入批量跑，看skill会不会出幻觉
- **红蓝对抗**：主动写"最可能导致skill失败"的输入，测到它稳定为止
- **生产埋点**：上线后记录真实用户的触发率/失败率/返工率——测试用例源于真实数据
