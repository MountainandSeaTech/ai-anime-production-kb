# Description触发条件写法

## 核心要点
- description被**注入系统提示词常驻**——它是skill的触发器，不是说明书
- 必须包含两个组件：**WHAT（做什么）+ WHEN（何时用）**，缺一个都是残疾
- **永远用第三人称**写——"Extracts text from PDFs"，不是"我可以帮你提取"
- 禁忌：在description里概述工作流程——模型会照着摘要执行，**跳过正文**，你精心设计的步骤直接白写

## 三段式公式
```
[具体产出物/能力] + [触发场景/关键词] + [负向边界]

示例（本机实际skill级水准）：
"从PDF提取文本和表格，支持合并拆分与表单填充。
 当用户需要读取、分析、批量处理PDF时使用；
 纯.docx编辑走docx skill，不用于PDF转图片。"
```

## WHAT的写法：具体，禁止"帮助"
```
❌ "Helps with video creation"     → 帮什么？怎么帮？等于没说
❌ "处理视频相关任务"               → 同上，中文一样废
✅ "Generate H3 anime fight-scene storyboard packages from character assets"
✅ "把分镜表转成逐镜头的AI视频提示词，含运镜/光影/表情参数"
```
- 第一原则：**命名产出物**，一句话说清做出来的是什么
- 只说what，永远不说how——how是正文的事（173）

## WHEN的写法：替用户把话说出来
用户不会念你的skill名，他们用自己的黑话提问。触发词要覆盖：

| 维度 | 内容 | 示例（以打戏分镜skill为例） |
|---|---|---|
| 正式术语 | 领域标准说法 | 分镜、storyboard、打戏编排 |
| 用户口语 | 用户实际会打的字 | "帮我排个打斗"、"对战画面" |
| 场景短语 | 任务出现的语境 | "H3分镜"、"fight prompt packs" |
| 工具联动 | 提及的上下游 | "角色设定图、场景设定图" |

- 实证参考本机skill：`h3-fight-storyboard`的description同时覆盖"打戏编排/对战分镜/fight prompt packs/资产提示词"四套说法——这才是触发词密度

## 负向边界：告诉Agent什么时候别来
```
"不用于新片段首版撰写"           （h3-storyboard-rework）
"不用于都市现实、纯言情"         （adventure-comedy-craft）
"Not for websites, apps, reports"（dynamic-ui）
```
- 没有负向边界的skill=见活就抢的卷王，污染所有相邻任务
- 边界写法：列出**最容易误判的相邻领域**，不用穷举全世界

## 好vs坏对照表

| 级别 | description | 诊断 |
|---|---|---|
| 死 | "一个视频处理工具" | 无what无when无边界，永不触发或永远误触发 |
| 残 | "创建动漫视频。当用户要动漫视频时使用" | 有what但太泛，when是同义反复 |
| 良 | "创作动漫短剧，覆盖剧本分镜到剪辑。用户要求AI短剧、漫剧时使用" | 能用，但缺边界，会抢PV/MV之外的活 |
| 优 | 上条+"不用于纯文字小说创作；长动画电影走anime-director" | what/when/边界三段齐全 |

## 常见坑
- **流程摘要中毒**："runs X, then Y, then reviews Z"——模型照此执行跳过正文，网络案例实测翻车
- **同义反复**："当用户需要X时使用"而what就是X——when字段零信息量
- **关键词洁癖**：只写正式术语，用户说人话时skill装死
- **边界膨胀**：负向列表写20条=description变成不要做什么清单，触发信号被稀释
- **多语言遗漏**：中英双语用户群只写英文触发词=丢一半流量（本机skill全部中英混排，学它）
- **超1024字符**：平台硬截断，后半段触发词直接蒸发

## 进阶
- **触发词测试矩阵**（178详解）：写10条用户可能的真实问法，逐条验证触发/不触发
- **竞品隔离**：同领域多个skill并存时，用边界句划清势力范围（如本机"日常搞笑"vs"疯批无敌流"vs"异世界冒险"三个写作skill的互斥声明）
- **版本漂移警惕**：skill能力扩展后忘改description=新能力永不触发，179维护流程里强制检查
- **A/B对照**：改description后跑一遍固定测试集，触发准确率下降就回滚

## 备注
- 三段式：产出物 + 触发场景 + 负向边界
- 写what别写how，流程是正文的事
- 触发词覆盖正式术语/口语/场景/工具四个维度
